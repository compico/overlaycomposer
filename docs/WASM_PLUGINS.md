# Серверные плагины на WebAssembly

Плагин — **один `.wasm`-файл**. Его можно написать на любом языке, который собирается в WebAssembly (Rust, Go, Zig, C…).
Манифеста нет: метаданные плагин отдаёт сам. Установка — положить файл в папку `ocplugs` рядом с программой
(или в папку плагинов профиля) и перезапустить OC / нажать «Перечитать».

Это не HTML-виджеты (`docs/PLUGINS.md`): wasm-плагин работает на сервере OC, у него нет окна и iframe. Он отвечает на HTTP-запросы,
получает события (награда Twitch, таймер, ответ на сетевой запрос) и хранит данные. Виджет и wasm-плагин могут работать вместе
через HTTP-маршруты плагина.

## Модель

* **Плагин пассивен.** Он ничего не слушает и не ждёт сам. Хост вызывает его: обработчик маршрута или `on_event`.
  Долгоживущими ресурсами (таймеры, сетевые запросы, EventSub) владеет хост.
* **Один экземпляр на плагин, вызовы по очереди.** Состояние хранится в `storage` хоста, а не в памяти плагина:
  после падения экземпляр пересоздаётся и ничего не теряет.
* **Супервизия.** Паника/trap/таймаут (10 с на вызов) → экземпляр пересоздаётся, ошибка уходит вызывающему.
  5 падений за минуту — плагин переходит в `failed` до ручного перезапуска.
* **Права.** Плагин запрашивает разрешения в `oc_meta`, пользователь их выдаёт. Операция без выдачи отклоняется,
  событие не доставляется. Безопасность wasm-песочницы — память и системные вызовы плагина изолированы; но всё, что
  разрешено (сеть, награды), плагин делает от имени пользователя, поэтому ставьте плагины только из источников, которым доверяете.
* **Выдача прав перезапускает плагин** (если набор изменился): `oc_init` выполняется заново уже с новыми правами. Поэтому в `oc_init` отказ в
  операции (например, таймер без права `timer`) — обычное состояние до выдачи прав, а не причина падать.
* **Время и случайность настоящие:** `time.Now()` и `crypto/rand` в плагине работают как обычно (часы хоста; в wasip1 нет часовых поясов — время в UTC).
* **Лог.** Всё, что плагин пишет через `log`, а также его stdout/stderr (текст паники Go) попадает в лог OC с пометкой `plugin=<id>`.

## SDK для Go

Писать ABI руками не нужно: модуль `github.com/compico/overlaycomposer/pkg/ocplugin` (без зависимостей, отдельный `go.mod`)
даёт `New`, `GET/POST/…`, `OnRedemption`, `OnTimer`, `Load/Store`, `Fetch` и остальное. См. `pkg/ocplugin/README.md`.
Ниже — сам ABI: он нужен авторам на других языках и тем, кто хочет понять, что происходит под капотом.

## ABI (JSON поверх линейной памяти)

Сигнатуры не меняются; всё остальное — JSON, поэтому добавление возможностей не ломает уже собранные плагины.
`i64` = `(ptr << 32) | len` — буфер в памяти плагина; `0` — пусто.

| Экспорт плагина | Назначение |
|---|---|
| `alloc(n: i32) -> i32` | выделить `n` байт (не менее 1) |
| `dealloc(ptr: i32)` | освободить буфер |
| `oc_meta() -> i64` | **чистая** функция: JSON метаданных (хост вызывает её на одноразовом экземпляре, `host_call` там недоступен) |
| `oc_init(ptr, len) -> i64` | `{"apiVersion":1,"config":{…}}`; здесь можно просить таймеры; результат игнорируется |
| `oc_call(name_ptr, name_len, arg_ptr, arg_len) -> i64` | обработчик маршрута (по имени из `oc_meta`) или `on_event` |

| Импорт (модуль `oc`) | Назначение |
|---|---|
| `host_call(op_ptr, op_len, arg_ptr, arg_len) -> i64` | операция хоста; JSON-аргумент → JSON-ответ |

Буфер, который плагин вернул хосту, хост читает и освобождает через `dealloc`. Буфер, который хост вернул плагину
(через `alloc` плагина), плагин освобождает сам. Плагин-реактор: Go — `GOOS=wasip1 GOARCH=wasm go build -buildmode=c-shared`
с `//go:wasmexport`/`//go:wasmimport`; Rust — `cdylib` для `wasm32-wasip1`. Если экспортирован `_initialize`, хост его вызывает.

### oc_meta

```json
{
  "id": "music", "name": "Music requests", "version": "0.1.0", "apiVersion": 1,
  "description": "…", "author": "…",
  "permissions": ["storage", "timer", "net.http", "twitch.redemption"],
  "subscriptions": ["twitch.redemption"],
  "routes": [{"method": "GET", "path": "/next", "handler": "next"}],
  "configSchema": {"rewardId": {"type": "string", "title": "Награда"}}
}
```

* `id` — `a-z`, `0-9`, `-`, до 64 символов; не должен совпадать с id HTML-плагина.
* `version` — semver. `apiVersion` — сейчас `1`.
* Маршрут доступен как `/plugins/<id>/api<path>` (методы GET/POST/PUT/PATCH/DELETE). Имя обработчика `on_event` занято.
* Подписка `twitch.redemption` требует разрешения `twitch.redemption`.

### Маршруты

Обработчик получает `{"method","path","query":{…},"body":<json|null>}` и возвращает `{"status":200,"body":<json>}`
(статус по умолчанию 200; пустой ответ — 204). **Обработчик отвечает сразу**: результат долгой работы приходит событием и
кладётся в storage, а клиент забирает его следующим запросом.

### События (`on_event`)

Аргумент — `{"type": "...", "data": {...}}`.

| type | когда | data | нужно |
|---|---|---|---|
| `twitch.redemption` | зритель получил награду | данные погашения Twitch | подписка + разрешение `twitch.redemption` |
| `timer` | сработал таймер плагина | `{"id"}` | разрешение `timer` |
| `http.response` | пришёл ответ на `http.fetch` | `{"id","status","body","error"}` | разрешение `net.http` |

События доставляются по очереди; очередь ограничена (256), при переполнении событие отбрасывается с записью в лог.

### Операции хоста (`host_call`)

| op | аргумент | ответ | разрешение |
|---|---|---|---|
| `log` | `{"level","msg","fields"}` | — | — |
| `storage.get` | `{"key"}` | `{"found":bool,"value":<json>}` | `storage` |
| `storage.set` | `{"key","value":<json>}` | `{}` | `storage` |
| `storage.delete` | `{"key"}` | `{}` | `storage` |
| `timer.set` | `{"id","ms","repeat"}` — 50 мс…24 ч, до 16 таймеров, тот же `id` заменяет | `{}` | `timer` |
| `timer.clear` | `{"id"}` | — | `timer` |
| `http.fetch` | `{"id","method","url","body"}` — асинхронно, ответ придёт `http.response` | `{}` | `net.http` |
| `twitch.redemption.update` | `{"rewardId","id","status":"FULFILLED"\|"CANCELED"}` | `{}` | `twitch.redemption` |

Ошибка операции — `{"error":"…"}` вместо результата.

`http.fetch`: только `http(s)`; тело запроса до 256 КБ, ответа до 1 МБ, 15 с, не более 8 запросов одновременно, до 3 редиректов.
Адреса **loopback, частных сетей, link-local и CGNAT запрещены** (проверка при соединении, после DNS, поэтому подмена DNS не помогает) —
плагин не может ходить к локальным сервисам пользователя.

## Для разработчика хоста

Пакет `internal/wasmplugins`: `Manager` (поиск, загрузка, права, настройки, маршруты, события) поверх интерфейсов
`Engine`/`Module`/`Instance`; `WazeroEngine` — реализация на [wazero](https://wazero.io) (чистый Go, без cgo).
Логика проверяется на фейковом движке (`fake_test.go`), связка с настоящим wasm — `wazero_test.go`
(собирает `testdata/guest` через `go build`).

## Установка и HTTP-интерфейс хоста

Папки поиска: `ocplugs` в профиле (рядом с `plugins`; при `--home` — внутри него) и `ocplugs` рядом с программой.
Плагины читаются при запуске и по кнопке «Перечитать»; изменённый файл перезапускается, исчезнувший выгружается.
Права и настройки лежат в `data/wasmplugins.json` (не в kv: настройки могут содержать токены), кэш компиляции — в `data/wasm-cache`.

Маршруты плагина — `/plugins/<id>/api<path>`. Запись из чужого origin (в том числе из sandbox-iframe виджета) отклоняется общей
защитой, с других устройств нужен токен. GET-обработчики должны быть без побочных эффектов — их можно вызвать с любой страницы.
Ответ всегда `application/json`; внутренние ошибки плагина наружу не попадают (500 `plugin error`).

Управление (только с этого компьютера, изменения — с заголовком `X-Overlay-Composer: 1`):

| Запрос | Что делает |
|---|---|
| `GET /api/wasmplugins` | плагины (метаданные, состояние, выданные права, настройки), проблемные файлы, состояние EventSub |
| `POST /api/wasmplugins/reload` | перечитать папки |
| `PUT /api/wasmplugins/:id/grants` `{"granted":[…]}` | заменить набор разрешений |
| `PUT /api/wasmplugins/:id/config` `{…}` | сохранить настройки и перезапустить плагин |
| `POST /api/wasmplugins/:id/restart` | перезапустить (в том числе из состояния `failed`) |
| `GET /api/twitch/rewards`, `POST /api/twitch/rewards` | награды канала: список и создание (409 — нет аккаунта или прав) |

EventSub включается автоматически, пока есть плагин, подписанный на `twitch.redemption` и получивший это разрешение, и выключается,
когда такого нет. Повторные доставки одного погашения (после переподключения) отсекаются по id.
