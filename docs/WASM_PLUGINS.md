# Автономные (standalone) плагины на WebAssembly

Плагин — **один `.wasm`-файл**. Его можно написать на любом языке, который собирается в WebAssembly (Rust, Go, Zig, C…).
Манифеста нет: метаданные плагин отдаёт сам. Установка — положить файл в папку плагинов (ту же, что у обычных плагинов-виджетов: кнопка
«Open folder» в окне «Standalone plugins…» открывает её) и нажать «Rescan» там же или перезапустить OC.

Это не HTML-виджеты (`docs/PLUGINS.md`): wasm-плагин работает на сервере OC, у него нет окна и iframe. Он отвечает на HTTP-запросы,
получает события (награда Twitch, таймер, ответ на сетевой запрос) и хранит данные. Виджет и wasm-плагин могут работать вместе
через HTTP-маршруты плагина.

## Модель

* **Плагин пассивен.** Он ничего не слушает и не ждёт сам. Хост вызывает его: обработчик маршрута или `on_event`.
  Долгоживущими ресурсами (таймеры, сетевые запросы, EventSub) владеет хост.
* **Один экземпляр на плагин, вызовы по очереди.** Состояние хранится в `storage` хоста, а не в памяти плагина:
  после падения экземпляр пересоздаётся и ничего не теряет.
* **Супервизия.** Паника/trap/таймаут (10 с на вызов) → экземпляр пересоздаётся, ошибка уходит вызывающему.
  5 падений за минуту — плагин переходит в `failed` до ручного перезапуска.
* **Права.** Плагин запрашивает разрешения в `oc_meta`, пользователь их выдаёт. Операция без выдачи отклоняется,
  событие не доставляется. Безопасность wasm-песочницы — память и системные вызовы плагина изолированы; но всё, что
  разрешено (сеть, награды), плагин делает от имени пользователя, поэтому ставьте плагины только из источников, которым доверяете.
* **Выдача прав перезапускает плагин** (если набор изменился): `oc_init` выполняется заново уже с новыми правами. Поэтому в `oc_init` отказ в
  операции (например, таймер без права `timer`) — обычное состояние до выдачи прав, а не причина падать.
* **Время и случайность настоящие:** `time.Now()` и `crypto/rand` в плагине работают как обычно (часы хоста; в wasip1 нет часовых поясов — время в UTC).
* **Лог.** Всё, что плагин пишет через `log`, а также его stdout/stderr (текст паники Go) попадает в лог OC с пометкой `plugin=<id>`.

## SDK для Go

Писать ABI руками не нужно: модуль `github.com/compico/overlaycomposer/pkg/ocplugin` (без зависимостей, отдельный `go.mod`)
даёт `New`, `GET/POST/…`, `OnRedemption`, `OnTimer`, `Load/Store`, `Fetch` и остальное. См. `pkg/ocplugin/README.md`.
Ниже — сам ABI: он нужен авторам на других языках и тем, кто хочет понять, что происходит под капотом.

## ABI (JSON поверх линейной памяти)

Сигнатуры не меняются; всё остальное — JSON, поэтому добавление возможностей не ломает уже собранные плагины.
`i64` = `(ptr << 32) | len` — буфер в памяти плагина; `0` — пусто.

| Экспорт плагина | Назначение |
|---|---|
| `alloc(n: i32) -> i32` | выделить `n` байт (не менее 1) |
| `dealloc(ptr: i32)` | освободить буфер |
| `oc_meta() -> i64` | **чистая** функция: JSON метаданных (хост вызывает её на одноразовом экземпляре, `host_call` там недоступен) |
| `oc_init(ptr, len) -> i64` | `{"apiVersion":1,"config":{…}}`; здесь можно просить таймеры; результат игнорируется |
| `oc_call(name_ptr, name_len, arg_ptr, arg_len) -> i64` | обработчик маршрута (по имени из `oc_meta`) или `on_event` |

| Импорт (модуль `oc`) | Назначение |
|---|---|
| `host_call(op_ptr, op_len, arg_ptr, arg_len) -> i64` | операция хоста; JSON-аргумент → JSON-ответ |

Буфер, который плагин вернул хосту, хост читает и освобождает через `dealloc`. Буфер, который хост вернул плагину
(через `alloc` плагина), плагин освобождает сам. Плагин-реактор: Go — `GOOS=wasip1 GOARCH=wasm go build -buildmode=c-shared`
с `//go:wasmexport`/`//go:wasmimport`; Rust — `cdylib` для `wasm32-wasip1`. Если экспортирован `_initialize`, хост его вызывает.

### oc_meta

```json
{
  "id": "music", "name": "Music requests", "version": "0.1.0", "apiVersion": 1,
  "description": "…", "author": "…",
  "permissions": ["storage", "timer", "net.http", "twitch.redemption"],
  "netLocal": [{"target": "127.0.0.1:24050", "setting": "tosuHost", "paths": ["/files/beatmap/"],
               "streams": [{"path": "/websocket/v2", "topic": "live", "fields": {"file": "directPath.beatmapFile"}, "minIntervalMs": 250}]}],
  "subscriptions": ["twitch.redemption"],
  "routes": [{"method": "GET", "path": "/next", "handler": "next"}],
  "configSchema": {"rewardId": {"type": "string", "title": "Награда"}}
}
```

* `id` — `a-z`, `0-9`, `-`, до 64 символов; не должен совпадать с id HTML-плагина.
* `version` — semver. `apiVersion` — сейчас `1`.
* Маршрут доступен как `/plugins/<id>/api<path>` (методы GET/POST/PUT/PATCH/DELETE). Имя обработчика `on_event` занято.
* Подписка `twitch.redemption` требует разрешения `twitch.redemption`.
* Подписка `chat.command` требует разрешения `chat.command.read` и непустого `commands` — списка команд без `!`
  (`["np"]`; строчные латиница, цифры, `_`, до 32 символов, не более 16 команд). `commands` без подписки не допускается.

### Маршруты

Обработчик получает `{"method","path","query":{…},"body":<json|null>}` и возвращает `{"status":200,"body":<json>}`
(статус по умолчанию 200; пустой ответ — 204). **Обработчик отвечает сразу**: результат долгой работы приходит событием и
кладётся в storage, а клиент забирает его следующим запросом.

### События (`on_event`)

Аргумент — `{"type": "...", "data": {...}}`.

| type | когда | data | нужно |
|---|---|---|---|
| `twitch.redemption` | зритель получил награду | данные погашения Twitch | подписка + разрешение `twitch.redemption` |
| `chat.command` | зритель написал в чате команду из `commands` плагина | `ChatCommand` (см. ниже) | подписка + разрешение `chat.command.read` |
| `timer` | сработал таймер плагина | `{"id"}` | разрешение `timer` |
| `http.response` | пришёл ответ на `http.fetch` | `{"id","status","body","error"}` | разрешение `net.http` |

#### Команды чата (`chat.command`)

OC читает чат канала по умолчанию (из настроек OC) и выбирает сообщения, начинающиеся с `!` сразу перед именем команды
(`!np`, `!info @compico`; `! np`, `!!np`, `!привет` — не команды). Плагин получает **только** команды из своего `commands`:
остальной чат ему недоступен, а плагин без этих команд не просыпается. Разрешение `chat.command.read` отдельное от чтения чата.
Сообщения `/me` и сообщения самого бота командами не считаются.

```json
{"command": "np", "args": ["@compico"], "channel": "compico", "userId": "1", "user": "viewer", "displayName": "Viewer",
 "messageId": "…", "isBroadcaster": false, "isMod": true, "isVip": false, "isSub": true, "timestamp": 1700000000000}
```

`command` — без `!`, в нижнем регистре; `args` — слова после команды (разделитель — пробел, регистр сохранён, до 16 слов по 200 символов).
Аргументы и ники — текст зрителей, ему нельзя доверять. Права («кто может») и паузы между вызовами плагин проверяет сам по `is*`.
В SDK: `Meta.Commands`, `p.OnChatCommand(func(ocplugin.ChatCommand){…})`, `ocplugin.PermChatCommandRead`; ответить в чат — `ocplugin.Say` (`chat.send`).

События доставляются по очереди; очередь ограничена (256), при переполнении событие отбрасывается с записью в лог.

### Операции хоста (`host_call`)

| op | аргумент | ответ | разрешение |
|---|---|---|---|
| `log` | `{"level","msg","fields"}` | — | — |
| `storage.get` | `{"key"}` | `{"found":bool,"value":<json>}` | `storage` |
| `storage.set` | `{"key","value":<json>}` | `{}` | `storage` |
| `storage.delete` | `{"key"}` | `{}` | `storage` |
| `timer.set` | `{"id","ms","repeat"}` — 50 мс…24 ч, до 16 таймеров, тот же `id` заменяет | `{}` | `timer` |
| `timer.clear` | `{"id"}` | — | `timer` |
| `http.fetch` | `{"id","method","url","body"}` — асинхронно, ответ придёт `http.response` | `{}` | `net.http`; для адреса из `netLocal` — `net.local` |
| `twitch.redemption.update` | `{"rewardId","id","status":"FULFILLED"\|"CANCELED"}` | `{}` | `twitch.redemption` |
| `events.publish` | `{"topic","data","retain"}` | `{}` | `events.publish` |
| `chat.send` | `{"text"}` | `{}` | `chat.send` |

Ошибка операции — `{"error":"…"}` вместо результата.

`chat.send` (`ocplugin.Say`): сообщение в чат канала стримера **от бота**. Канал и аккаунт выбирает хост (плагин их указать не может);
текст до 300 символов; частота: всплеск 3 сообщения, затем одно в 3 секунды, лишнее отклоняется. Отправка идёт в фоне: `{}` значит «принято»,
а нет аккаунта бота или связи с чатом — запись в логе OC. Без разрешения `chat.send` операция отклоняется.

`http.fetch`: только `http(s)`; тело запроса до 256 КБ, ответа до 1 МБ, 15 с, не более 8 запросов одновременно, до 3 редиректов.
Адреса **loopback, частных сетей, link-local и CGNAT запрещены** (проверка при соединении, после DNS, поэтому подмена DNS не помогает) —
плагин не может ходить к локальным сервисам пользователя.

## Статика и виджеты

Плагин может нести интерфейс — HTML, js, css, картинки, шрифты. Всё это лежит **внутри того же `.wasm`**, в custom section `oc.assets`
(zip-архив). Плагин остаётся одним файлом: его так же кладут в папку плагинов, `sha256` релиза покрывает и код, и интерфейс,
а секция дописывается к уже собранному модулю на любом языке, без перекомпиляции. Хост читает её при сканировании
(плагин для этого не запускается) и отдаёт сам из памяти: `/plugins/<id>/ui/<путь>`.

Упаковка — утилита `ocpack` (отдельная консольная программа, к приложению с треем отношения не имеет):

```
go run ./cmd/ocpack pack music.wasm ./ui          # дописать секцию (повторный запуск заменяет прежнюю)
go run ./cmd/ocpack pack music.wasm ./ui -o out.wasm
go run ./cmd/ocpack list out.wasm                 # что внутри
```

Результат детерминирован (порядок файлов и даты фиксированы). Формат простой — custom section `oc.assets` с обычным zip, —
поэтому архив можно собрать и любым другим инструментом.

### Упаковка в CI (GitHub Actions)

В репозитории есть готовое действие `actions/ocpack`: собирает `ocpack` из той же ревизии, что и действие (бинарников не скачивает),
и упаковывает статику в `.wasm`. Закрепляйте его за тегом релиза или коммитом. Работает на Linux и macOS раннерах.

```yaml
- name: Сборка плагина
  run: GOOS=wasip1 GOARCH=wasm go build -buildmode=c-shared -o music.wasm ./wasm/music
- name: Упаковка интерфейса
  uses: compico/overlaycomposer/actions/ocpack@<тег-или-коммит>
  with:
    wasm: music.wasm
    ui: wasm/music/ui
    # output: dist/music.wasm   # по умолчанию файл заменяется
```

Выход `file` — путь к готовому файлу. Упаковка повторяема: тот же вход даёт тот же `.wasm`, поэтому `sha256` в релизе воспроизводим.

Правила (нарушение — плагин не загружается, причина видна в списке проблем):
- пути относительные, с `/`, символы `A–Z a–z 0–9 . _ ~ @ -`, без `..`, без скрытых файлов (при упаковке `.DS_Store`, `.git` пропускаются);
- расширения только из списка: html, htm, js, mjs, css, json, txt, png, jpg, jpeg, gif, webp, svg, ico, woff, woff2, mp3, ogg, wav;
- не более 256 файлов, файл до 2 МБ, всего до 8 МБ; имена, отличающиеся только регистром, не допускаются.

Виджеты объявляются в метаданных (`Meta.Widgets` в Go SDK): `{id, name, entry, width, height}`, `entry` — HTML-файл из статики.
Если файла нет в архиве, плагин не загружается.

Безопасность: страница плагина — чужой код. Каждый ответ статики идёт с `Content-Security-Policy: sandbox allow-scripts`, поэтому даже
открытая напрямую она получает «непрозрачный» origin и не может обратиться к API приложения. Виджет показывается в iframe с `sandbox`
без `allow-same-origin`, как и обычные виджеты (`docs/PLUGINS.md`). Маршруты `/plugins/<id>/api/*` по-прежнему отдают только JSON.

### Виджет на сцене

Виджеты загруженных автономных плагинов появляются в «Add Source → Plugins» рядом с обычными (с пометкой «standalone»).
Источник хранит `plugin` (id плагина) и `widget` (id виджета), а iframe открывает `/plugins/<id>/widget/<виджет>` — редирект
на страницу из статики плагина (`/plugins/<id>/ui/<entry>`); относительные адреса внутри HTML (`app.js`) работают от `/ui/`.
В HTML подключайте SDK как у обычных виджетов (`/plugin-sdk/oc.js`, см. `docs/PLUGINS.md`).

Связь виджета со своим плагином — `oc.plugin.call(method, path, {query, body})` (и `oc.plugin.get/post`). Запрос идёт не по HTTP
из iframe (у sandbox `Origin: null`, CORS на API плагина не нужен и не включается), а через страницу OC и существующий `/ws`:

- адресат всегда плагин этого виджета, а не то, что прислал виджет; сервер дополнительно проверяет, что источник существует
  и является виджетом именно этого плагина;
- вызвать можно только маршрут, объявленный плагином; методы GET/POST/PUT/PATCH/DELETE, тело до 1 МБ, ответ — `{status, body}`;
- не больше 8 одновременных вызовов на всё приложение, таймаут 15 с; внутренние причины сбоя плагина виджету не раскрываются.

```js
const { body } = await oc.plugin.get("/queue");          // GET /plugins/music/api/queue
await oc.plugin.post("/started", { id: "…" });           // POST …/started
```

Предпросмотр в редакторе тоже вызывает плагин (`info.preview === true`): не отправляйте оттуда действия, которые сами меняют
состояние. Настроек у виджета автономного плагина пока нет; разрешения плагина (storage, Twitch…) выдаются в «Standalone plugins…».

## Установка и HTTP-интерфейс хоста

Папка поиска — `PluginsDir` (папка плагинов профиля, при `--home` — внутри него): `.wasm`-файлы лежат прямо в ней, рядом с подпапками
HTML-плагинов (менеджер читает только файлы, реестр HTML-плагинов — только подпапки с `plugin.json`).
Плагины читаются при запуске и по кнопке «Rescan»; изменённый файл перезапускается, исчезнувший выгружается.
Права и настройки лежат в `data/wasmplugins.json` (не в kv: настройки могут содержать токены), кэш компиляции — в `data/wasm-cache`.

Права, настройки (в том числе выбор или создание награды Twitch), перезапуск и открытие папки — в редакторе: «Plugin store… → Standalone plugins…».
Форма настроек строится из `configSchema` плагина: поля `string`, `integer`/`number`, `boolean`; `"format": "twitch.reward"` даёт выбор награды.

Маршруты плагина — `/plugins/<id>/api<path>`. Запись из чужого origin (в том числе из sandbox-iframe виджета) отклоняется общей
защитой, с других устройств нужен токен. GET-обработчики должны быть без побочных эффектов — их можно вызвать с любой страницы.
Ответ всегда `application/json`; внутренние ошибки плагина наружу не попадают (500 `plugin error`).

Исключение — окно Яндекс Музыки. Аддоны PulseSync исполняются внутри него и ходят в OC обычным браузерным `fetch` с origin
`music-application://desktop`, поэтому для их `POST` нужны CORS и ответ на preflight (`OPTIONS`). Этому origin (точное совпадение)
и только на маршрутах `/plugins/<id>/api/*` OC отвечает на preflight (204) и пропускает запись; `Access-Control-Allow-Origin`
содержит именно его, а не `*`. Остальной `/api/*`, WebSocket, страницы приложения и любые другие origin закрыты как раньше, а проверка
Host (защита от DNS rebinding) и токен для других устройств действуют и для него. Веб-страница не может выставить такой origin,
а другое приложение на компьютере и так отправляет запросы без `Origin`.

Управление (только с этого компьютера, изменения — с заголовком `X-Overlay-Composer: 1`):

| Запрос | Что делает |
|---|---|
| `GET /api/wasmplugins` | плагины (метаданные, состояние, выданные права, настройки), проблемные файлы, состояние EventSub |
| `POST /api/wasmplugins/reload` | перечитать папки |
| `PUT /api/wasmplugins/:id/grants` `{"granted":[…]}` | заменить набор разрешений |
| `PUT /api/wasmplugins/:id/config` `{…}` | сохранить настройки и перезапустить плагин |
| `POST /api/wasmplugins/:id/restart` | перезапустить (в том числе из состояния `failed`) |
| `GET /api/twitch/rewards`, `POST /api/twitch/rewards` | награды канала: список и создание (409 — нет аккаунта или прав) |

EventSub включается автоматически, пока есть плагин, подписанный на `twitch.redemption` и получивший это разрешение, и выключается,
когда такого нет. Повторные доставки одного погашения (после переподключения) отсекаются по id.

## Страница настроек плагина

Плагин может объявить в метаданных `settings` — путь HTML-файла в статике (`ui/…`, секция `oc.assets`), например `"settings": "settings.html"`.
Тогда в окне «Plugins» у плагина появляется кнопка «Settings»; она открывает окно, где сверху форма настроек OC
(по `configSchema`, включая выбор награды Twitch), а ниже страница плагина в sandbox-iframe. Страница получает тот же мост
`oc.*`, что и виджеты: `oc.plugin.get/post` вызывают маршруты **своего** плагина (адресат определяется по окну, а не по
содержимому сообщения), `oc.storage.*` работает при разрешении `storage`. Сервер принимает такие вызовы без источника только
для плагина, который объявил `settings`.

## События (pub/sub): публикация

Плагин может **публиковать события** для подписчиков (виджеты, аддоны, deck). Нужно разрешение `events.publish` (`ocplugin.PermPublish`)
и объявление топиков в метаданных:

```go
Events: []ocplugin.EventDecl{{ID: "now", Name: "Сейчас играет"}, {ID: "commands"}},
```

- `ocplugin.Publish("commands", v)` публикует событие; `ocplugin.PublishRetained("now", v)` ещё и просит хост хранить последнее
  значение топика, чтобы новый подписчик получил его сразу (для состояния, не для команд).
- Топик: `a-z0-9._-`, до 64 символов, до 32 топиков на плагин. Публиковать можно только **объявленные** топики, и только в своём
  пространстве имён: его задаёт хост по id плагина, а не вызов.
- Данные: корректный JSON до 64 КБ. Частота ограничена на плагин (в среднем 20 событий/с, всплеск 40); лишнее отбрасывается и возвращает ошибку.
- Подписчик с медленным соединением не тормозит плагин: его очередь ограничена, при переполнении теряются самые старые события.

### Подписка из виджета и страницы настроек

```js
oc.plugin.subscribe("now", (data, meta) => { /* data — JSON события; meta = { topic, seq, retained } */ });
```

Виджет плагина и его страница настроек могут подписаться на **объявленные** топики **своего** плагина. Если у топика есть
сохранённое значение, оно приходит сразу (`retained: true`), дальше — свежие события с растущим `seq`. Мост сам восстанавливает
подписки после переподключения `/ws` и снимает их, когда окно закрыто. На уровне `/ws` это сообщения `plugin:sub` / `plugin:unsub`
(ответ `plugin:sub:result`) и события `plugin:event`; сервер проверяет окно так же, как для `plugin:call`, подписок на соединение — не больше 64.

### Внешний WebSocket: `/plugins/<id>/ws`

Для клиентов вне страниц OC — аддонов PulseSync, deck на планшете, скриптов. Только подписка (вызывать маршруты плагина можно обычным HTTP).
Кадры — текстовый JSON (работает и в Safari 9):

| направление | кадр |
|---|---|
| клиент → | `{"t":"sub","topic":"now"}`, `{"t":"unsub","topic":"now"}`, `{"t":"ping"}` |
| сервер → | `{"t":"hello","plugin":"music"}` при подключении |
| | `{"t":"sub","topic":"now","ok":true}` или `…"ok":false,"error":"unknown topic"}` |
| | `{"t":"event","topic":"now","data":…,"seq":7,"retained":true}` |
| | `{"t":"pong"}` |

- Origin: допускаются запросы без Origin, с Origin того же хоста и `music-application://desktop` (аддоны PulseSync); остальные, включая `null`, получают 403.
- Сервер раз в 20 с шлёт управляющий ping (браузер отвечает сам); соединение, из которого ничего не приходит 70 с, закрывается. Клиент без доступа к управляющим кадрам шлёт `{"t":"ping"}`.
- Лимиты: 64 внешних соединения, 32 подписки на соединение, кадр клиента до 4 КБ, до 20 сообщений/с. Медленный клиент теряет события (смотрите `seq`), на плагин и других подписчиков это не влияет.
- Нужен ли переподключаться: да, клиент сам; после `sub` retained-значение приходит снова, поэтому состояние восстанавливается.

## Программа на этом компьютере (`net.local`)

`http.fetch` с разрешением `net.http` ходит только в интернет: loopback, частные сети и link-local закрыты. Если плагину нужна программа на
этом же компьютере (например, tosu отдаёт файлы карт на `127.0.0.1:24050`), он объявляет её в `oc_meta` и просит разрешение `net.local`:

```json
"permissions": ["net.local"],
"netLocal": [{"target": "127.0.0.1:24050", "setting": "tosuHost", "paths": ["/files/beatmap/"]}]
```

- `target` — `host:port` на этом компьютере (`127.0.0.1`, `localhost` или `[::1]`); до 4 целей.
- `setting` — необязательное имя строковой настройки: пользователь может заменить адрес (если порт нестандартный).
- `paths` — необязательные префиксы пути; сегменты `.` и `..` в пути запрещены (разделители `/` и `\`).
- `http.fetch` на объявленный адрес требует именно `net.local` (`net.http` его не заменяет). Идёт по `http`, без редиректов,
  соединение принимается только с loopback, ответ может быть до 8 МиБ (в интернет — 1 МиБ).
- Любой другой локальный адрес по-прежнему закрыт. Пользователь в «Standalone plugins…» видит, к каким адресам плагин получит доступ.

## Потоки net.local: ретранслятор websocket

Локальные программы (tosu) не пускают websocket из виджета: iframe плагина в sandbox, браузер шлёт `Origin: null`. Опрос HTTP через `Fetch`
будит wasm на каждый запрос и заметно грузит процессор. Поэтому плагин может объявить поток в `netLocal[].streams`:

```json
{"path": "/websocket/v2", "topic": "live", "fields": {"file": "directPath.beatmapFile", "time": "beatmap.time.live"}, "minIntervalMs": 250}
```

- хост сам подключается к `ws://<target><path>` (без `Origin`, только loopback, без прокси) и **только пока у топика есть подписчики**; при обрыве переподключается с паузой 1–15 с;
- из каждого JSON-кадра берутся поля `fields` (имя → путь через точки; нет поля — `null`), объект публикуется в топик (`retain`: новый подписчик сразу получает последнее значение);
- кадры чаще `minIntervalMs` (по умолчанию 250 мс, 100…60000) отбрасываются без разбора JSON; неизменившееся значение не публикуется;
- топик обязан быть объявлен в `events`; нужно разрешение `net.local`; не больше 2 потоков на плагин и 16 полей на поток; кадр до 4 МиБ, событие до 64 КБ;
- виджет получает данные через `oc.plugin.subscribe(topic, cb)`, wasm не вызывается.

## Настройки виджета

У виджета есть собственные настройки: у каждого источника на сцене они свои, редактор строит по ним форму (в том числе выпадающий список), а значения
приходят виджету как `?key=value`. Формат тот же, что у `settings` в `plugin.json` HTML-плагинов (типы `string`, `text`, `number`, `range`, `bool`, `color`,
`font`, `select`; см. docs/PLUGINS.md), до 32 настроек на виджет:

```go
Widgets: []ocplugin.Widget{{ID: "graph", Name: "Graph", Entry: "index.html", Settings: []ocplugin.WidgetSetting{
    {Key: "style", Label: "Style", Type: "select", Default: "ribbon",
        Options: []ocplugin.SettingOption{{Value: "ribbon", Label: "Ribbon"}, {Value: "bars", Label: "Bars"}}},
}}},
```

В виджете: `oc.param("style", "ribbon")`. Редактор сохраняет только изменённые значения, поэтому умолчание должно быть и в коде виджета.
Настройки плагина (`configSchema`) остаются для того, что общее для всего плагина (адреса, токены).
