# Плагины-виджеты

Плагин — папка с `plugin.json` и файлами виджета (HTML/JS/CSS/картинки/шрифты). Приложение раздаёт её по `/plugins/<id>/…`,
показывает виджет в iframe и строит в редакторе форму настроек по схеме из манифеста. Значения настроек виджет получает
**в query-параметрах** своего адреса: `/plugins/twitch-chat/?channel=shroud&msgSize=32`.

Куда класть: папка `plugins/` рядом с данными приложения (кнопка **Open plugins folder** в диалоге Add Source), по одной подпапке
на плагин. Перезапуск не нужен — список обновляется при открытии диалога Add Source. Встроенные плагины (например, `twitch-chat`)
зашиты в бинарник и не переопределяются.

```
plugins/
  my-widget/
    plugin.json
    index.html
    app.js
```

## plugin.json

```json
{
  "id": "my-widget",
  "name": "My widget",
  "version": "1.0.0",
  "description": "Что делает виджет",
  "entry": "index.html",
  "defaultSize": { "width": 480, "height": 200 },
  "settings": [
    { "key": "host", "label": "tosu host", "type": "string", "group": "Connection", "default": "127.0.0.1:24050" },
    { "key": "size", "label": "Font size", "type": "number", "default": 32, "min": 8, "max": 200 },
    { "key": "color", "label": "Color", "type": "color", "default": "#ffffff" },
    { "key": "mode", "label": "Mode", "type": "select", "default": "a",
      "options": [ { "value": "a", "label": "Mode A" }, { "value": "b", "label": "Mode B" } ] }
  ]
}
```

- `id` — `a-z A-Z 0-9 _ -`, до 64 символов; совпадающий с уже занятым (встроенным) id отвергается.
- `entry` — файл, который открывается по `/plugins/<id>/` (по умолчанию `index.html`).
- `defaultSize` — размер слоя при добавлении на layout.
- `permissions` — что плагину нужно от OC: `chat.read`, `chat.send`, `storage`, `net.local` (см. «API OC» ниже). Пользователь подтверждает их при добавлении виджета
  и может изменить в свойствах слоя; без разрешения вызов API отклоняется.
- `netLocal` — какие программы на этом компьютере плагин может читать через `oc.net.localGet` (нужно разрешение `net.local`). Без него запросы отклоняются.
  Список правил (до 8); у каждого — `paths` (префиксы пути, например `["/json/"]`) и адрес одним из способов:
  `"target": "127.0.0.1:24050"` — фиксированный, или `"setting": "tosuHost"` — адрес `host:port` берётся из строковой настройки виджета
  (порт тогда выбирает пользователь в форме виджета, а не плагин; если он не менял настройку — действует её `default`). Разрешён только loopback;
  порт самого Overlay Composer закрыт всегда. Сервер проверяет и выданное разрешение, и правила; до 60 запросов за 10 с и 4 одновременных на виджет.
  ```json
  "permissions": ["net.local"],
  "netLocal": [{ "setting": "tosuHost", "paths": ["/json/"] }]
  ```
- Типы настроек: `string`, `text` (многострочный), `number`, `range` (ползунок), `bool`, `color` (`#rrggbb`), `font` (имя шрифта, с подсказками), `select` (нужны `options`).
  `min`/`max`/`step` — для `number` и `range`; `group` — заголовок секции; `help` — подпись под полем.
- Редактор сохраняет **только изменённые** значения (кнопка ↺ возвращает к умолчанию), поэтому **значения по умолчанию должен знать и сам виджет**
  — они в манифесте нужны для формы, а в коде виджета — для запуска без параметра. Держите их одинаковыми.
- Значения в query: строка как есть, число — `32`, bool — `true`/`false`.

Плагин с ошибкой в манифесте пропускается, причина пишется в лог (`plugins: плагин пропущен`).

## Как читать настройки

```js
const q = new URLSearchParams(location.search);
const size = parseFloat(q.get("size")) || 32;
```
или короче, с приведением к типу значения по умолчанию (работает и внутри OC, и при открытии страницы напрямую): `oc.param("size", 32)`.

## API OC (`oc.js`)

Подключите SDK в `index.html` плагина — появится глобальный объект `oc`:

```html
<script src="/plugin-sdk/oc.js"></script>
```

**Полное описание типов — один файл [`web/sdk/oc.d.ts`](../web/sdk/oc.d.ts)** (его же отдаёт запущенный OC по `/plugin-sdk/oc.d.ts`).
Положите его рядом с плагином и добавьте `/// <reference path="oc.d.ts" />`, чтобы редактор подсказывал сигнатуры; этот файл достаточно передать и ИИ-помощнику —
по нему можно написать плагин, не читая остальной код.

```js
oc.chat.on("message", (m) => {
  if (m.text === "!hi" && !m.fromBot) oc.chat.say(`Hello, ${m.displayName}!`, { replyTo: m.id });
});
await oc.chat.subscribe();                       // канал аккаунта Стримера; или { channel: "shroud" }
```

| Метод | Разрешение | Что делает |
|---|---|---|
| `oc.ready` | — | промис со сведениями о виджете (`pluginId`, `sourceId`, `settings`, `permissions`, `preview`) |
| `oc.param(key, default)` | — | настройка из query, приведённая к типу `default` |
| `oc.chat.subscribe({channel?})` | `chat.read` | подписка на чат канала; события — через `oc.chat.on("message"｜"delete"｜"clear"｜"status", fn)` |
| `oc.chat.say(text, {channel?, as?, replyTo?})` | `chat.send` | написать в чат от имени бота (`as: "bot"`, по умолчанию) или стримера |

| `oc.net.localGet(target, path)` | `net.local` | GET к программе на этом компьютере (`127.0.0.1:порт`) → `{status, body}`; запрос делает сервер OC, поэтому он без `Origin` (из sandbox-iframe браузер шлёт `Origin: null`, и, например, tosu такие запросы блокирует) |
| `oc.storage.get/set/delete/list(prefix)` | `storage` | JSON-данные плагина по ключам (SQLite на этом компьютере) |
| `oc.storage.update(key, fn)` | `storage` | безопасное «прочитал → изменил → записал», даже если ключ меняет другая копия виджета |
| `oc.storage.onChange(fn)` | `storage` | уведомление, когда данные плагина изменила любая копия (оверлей, предпросмотр) |
| `oc.lifecycle.onStop(fn)` | — | вызывается, когда OC выключается: у обработчика есть до 3 с на сохранение данных (см. ниже) |

Хранилище (`storage`): данные принадлежат **плагину** (по `pluginId`) и общие для всех его виджетов и копий оверлея; чужие плагины их не видят.
Ключ — до 128 символов `A–Z a–z 0–9 _ . : / -`, значение — любой JSON до 256 КБ; квота плагина — 5000 ключей и 8 МБ.
Размер данных и кнопка **Erase data** — в свойствах слоя. Пример — список задач, который меняют командами чата, а показывает второй виджет:

```js
oc.chat.on("message", async (m) => {
  if (m.text.startsWith("!task ")) await oc.storage.update("tasks", (list = []) => [...list, m.text.slice(6)]);
});
oc.storage.onChange((c) => { if (c.key === "tasks") render(c.value || []); });
render((await oc.storage.get("tasks")) || []);
```

### Остановка приложения (плавное завершение)

Когда пользователь выходит из OC (Quit в трее или в настройках, Ctrl+C, завершение системы), перед остановкой сервера плагины получают сигнал и успевают сохранить данные:

```js
oc.lifecycle.onStop(async ({ reason, graceMs }) => {   // reason === "shutdown", graceMs === 3000
  await oc.storage.set("draft", currentState);          // сервер ещё работает: storage и chat.say доступны
});
```

- Все страницы OC (оверлей, редактор с предпросмотром) получают уведомление, передают его плагинам с обработчиком и отвечают серверу, когда те закончили. Сервер ждёт ответов **не дольше `graceMs` (3 с) + 1 с запаса**, потом выключается в любом случае.
- Обработчики всех копий плагина вызываются параллельно; исключение в одном не мешает остальным. Если обработчик не завершился за `graceMs`, остановка идёт дальше, не дожидаясь его (запись, которую он не успел отправить, потеряется).
- Остановка — **best-effort**: при аварийном завершении (kill -9, потеря питания, падение процесса) и если страница оверлея в OBS уже закрыта, вызова не будет. Важные данные сохраняйте сразу по мере изменения (`oc.storage.update`), а `onStop` используйте для «последнего слова» (несохранённый черновик, отметка «стрим закончился»).
- Плагин без обработчика остановку не замедляет. `onStop` возвращает функцию отписки. Закрытие вкладки/сцены — не остановка: для этого используйте обычные события страницы (`pagehide`), но асинхронные запросы в них могут не успеть.
- Сигнал приходит только пока OC работает: после его выхода плагин не получит ничего (включая «OC снова запущен» — страница оверлея переподключится сама, плагин при этом не перезагружается).

**Как это устроено.** OC держит одно анонимное соединение на чтение чата Twitch и по одному соединению на аккаунт, от имени которого пишут;
плагины общаются с ним через страницу оверлея (`postMessage` → общий `/ws`), а не открывают своих сокетов. Токены Twitch плагину не передаются.
Аккаунты (стример, бот) подключаются в Settings → Twitch accounts.

- В **предпросмотре редактора** `say` отключён (иначе ответы дублировались бы с оверлеем); чтение работает.
- Ответ на одно и то же сообщение (`replyTo`) с одним и тем же текстом отправляется один раз — даже если оверлей открыт в двух местах (например, в двух сценах OBS).
- Лимит отправки (≈18 сообщений за 30 с на бота); при превышении `say` отклоняется.
- Если страница открыта не в OC (`oc.hosted === false`), вызовы отклоняются — плагин может использовать запасной путь (так сделан встроенный `twitch-chat`: без разрешения `chat.read` он подключается к чату сам).
- API версии 1 (`oc.version`). Транспорт (postMessage) спрятан за `oc.*` и может смениться, например, на wasm-бэкенд, без изменений в плагинах.

## Ограничения (sandbox)

Виджет — чужой код, поэтому его iframe запускается с `sandbox="allow-scripts allow-forms allow-popups allow-modals"` **без** `allow-same-origin`:
- у страницы «непрозрачный» origin: нет доступа к API приложения, `localStorage`/cookie недоступны;
- сервер OC принимает WebSocket и изменяющие запросы только со своих страниц (проверка `Origin`), поэтому плагин не может обойти разрешения, подключившись к OC напрямую;
- `WebSocket` и `fetch` к внешним адресам работают (для `fetch` сервер должен отдавать CORS — например, tosu отдаёт), в том числе к `ws://127.0.0.1:24050` (tosu);
- свои файлы плагина (`/plugins/<id>/…`) отдаются с `Access-Control-Allow-Origin: *`, их можно загружать и `fetch`-ем.

Плагины запускают произвольный код в вашем OBS-оверлее — ставьте только те, которым доверяете.

## Публикация и магазин

Плагины можно раздавать репозиторием GitHub: в корне папка `plugins/`, внутри подпапки `plugins/<id>/` (имя папки = `id` из `plugin.json`, обязательны `plugin.json` и файл `entry`). Пример — [compico/oc-plugins](https://github.com/compico/oc-plugins).

Пошаговый гайд (структура репозитория, TypeScript с `oc.d.ts`, Vite/esbuild, CI, публикация) — в [`PLUGIN-REPO.md`](PLUGIN-REPO.md).

Пользователь добавляет репозиторий в **Add Source → Plugin store…** (`owner/repo`, `owner/repo@ветка_или_тег`, или ссылка github.com), видит каталог с версиями и запрашиваемыми правами и ставит/обновляет/удаляет плагины кнопками. Обновление предлагается, когда `version` в репозитории выше установленной — поднимайте версию при каждом изменении. Магазин не перезаписывает встроенные плагины и папки, положенные вручную.

**Что видит и чем защищён пользователь.** Каталог показывает версию, запрашиваемые права и коммит, из которого собран архив. При установке OC отправляет отпечаток (sha256 файлов плагина), который пользователь видел в каталоге; если автор успел изменить плагин (в той же ветке, даже без смены версии) — установка отклоняется, каталог нужно открыть заново. Обновление предлагается и тогда, когда файлы изменились без поднятия `version`; новые права при обновлении подтверждаются отдельно (уже выданные виджетам права не расширяются сами). Хотите зафиксировать код — подключайте тег или коммит: `owner/repo@v1.2.0`, `owner/repo@<sha>`.

**Приватные репозитории.** В диалоге магазина — раздел «Private repositories (GitHub token)»: fine-grained personal access token (только нужные репозитории, `Contents: Read-only`). Токен хранится зашифрованным, уходит только на `api.github.com` (на адрес скачивания, на который GitHub перенаправляет, не передаётся), в интерфейс и плагинам не отдаётся. Пока токен задан, все репозитории скачиваются через GitHub API (лимиты выше, чем у анонимных запросов).
