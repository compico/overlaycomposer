# Deck: панель управления для старых устройств

Страница `/deck` — крупные плитки в стиле Metro для iPad 3 / Safari 9 и подобных: одно касание — действие. Страницу целиком собирает сервер
(`internal/deck`, `html/template`): плитки, цвета и подписи уже в HTML, клиентский код — около 60 строк ES5 без зависимостей.

## Открыть
1. Сопряжение устройства — как для редактора (`/pair`). Если открыть `/deck` без токена, после ввода кода откроется именно панель.
2. Проба совместимости: `/deck/probe` показывает, что умеет браузер (WebSocket, Promise, flexbox…) и открывается ли тестовый WebSocket к OC.

## Раскладка
- Сетка 8×6 (альбомная ориентация, 1024×768). Плитка 1…4 клеток по каждой оси, без пересечений.
- До 8 страниц, до 48 плиток на странице, до 200 всего. Страницы переключаются вкладками сверху, плитка с действием `page` — переход.
- Пока раскладка не сохранена, показывается раскладка по умолчанию: плитка 2×2 на каждую сцену OBS (по 8 на странице).
- Хранится в таблице `settings` (`deck_layout`, JSON), ревизия `rev` растёт при каждом сохранении; устройство сравнивает её со своей и
  перерисовывается. Сброс на раскладку по умолчанию не откатывает счётчик (`deck_rev`).

Плитка: `id` (уникален во всей раскладке), `x y w h`, `label` (до 40 символов), `color` (имя из палитры Metro, не произвольный CSS), `icon`
(из фиксированного набора символов), `confirm` (опасное: выполняется вторым касанием), `action`.

Действия: `scene` — сменить сцену OBS (сцена должна быть в списке OBS), `page` — перейти на страницу.

## API
| метод | путь | |
|---|---|---|
| GET | `/deck?page=<id>` | страница (SSR) |
| GET | `/api/deck/state` | `{rev, online, scene}` — опрос раз в 2 с (позже заменится WebSocket) |
| POST | `/api/deck/press` | `{tile, confirm}` — нажатие; нужен заголовок `X-Overlay-Composer: 1` |
| GET | `/api/deck/layout` | раскладка + сцены, палитра, иконки, размер сетки (для редактора) |
| PUT | `/api/deck/layout` | сохранить; `rev` в теле должен совпасть с текущим, иначе 409 |
| DELETE | `/api/deck/layout` | вернуть раскладку по умолчанию |

## Безопасность
- Клиент присылает только `id` плитки. Действие берётся из сохранённой раскладки на сервере: устройство не может вызвать произвольный маршрут
  или сцену. Неизвестная плитка — 404; сцены, которой нет в OBS, — 404.
- Опасные плитки (`confirm`) сервер выполняет только с `confirm:true` (второе касание), иначе 409.
- Нажатия ограничены по частоте (всплеск 16, затем 8/с).
- Доступ с других устройств — по токену сопряжения (`authGuard`); `POST/PUT/DELETE` требуют заголовок приложения (защита от чужих страниц).
- Страница отдаётся с CSP: только свои inline-стили/скрипт и запросы на тот же адрес; метки и сцены экранирует `html/template`.
