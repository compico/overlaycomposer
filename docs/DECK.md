# Deck: панель управления для старых устройств

Страница `/deck` — крупные плитки в духе начального экрана Windows 8 для iPad 3 / Safari 9 и подобных: одно касание — действие.
Страницу целиком собирает сервер (`internal/deck`, `html/template`): плитки, цвета и подписи уже в HTML, клиентский код — ES5 без зависимостей.

## Открыть
1. Сопряжение устройства — как для редактора (`/pair`). Если открыть `/deck` без токена, после ввода кода откроется именно панель.
2. Проба совместимости: `/deck/probe` показывает, что умеет браузер (WebSocket, Promise, flexbox…) и открывается ли тестовый WebSocket к OC.

## Раскладка
- Клетка квадратная. Рядов всегда 4: высота экрана делится на ряды (плюс строка заголовка группы), поэтому поворот устройства меняет только
  размер клетки и число видимых колонок, а не раскладку. Дальше — прокрутка вправо (палец, `-webkit-overflow-scrolling`).
- Плитки собраны в **группы** с заголовками; группы идут слева направо. Ширина группы — по самой правой плитке (до 16 колонок).
- Размеры плиток (ширина × высота в клетках): **1×1**, **2×1** (широкая: названия сцен и треков), **3×1** (очень широкая) и **2×3** (крупная, для редких случаев).
- До 16 групп, до 200 плиток. Страниц нет: их заменяют группы и прокрутка.
- Пока раскладка не сохранена, показывается раскладка по умолчанию: плитка 2×1 на каждую сцену OBS (в порядке OBS), столбцами по 4, группами по 8 сцен.
- Хранится в таблице `settings` (`deck_layout`, JSON), ревизия `rev` растёт при каждом сохранении; устройство сравнивает её со своей и
  перерисовывается (положение прокрутки сохраняется). Сброс на раскладку по умолчанию не откатывает счётчик (`deck_rev`).

Плитка: `id` (уникален во всей раскладке), `x y w h` (клетки внутри группы), `label` (до 40 символов), `color` (имя из палитры Metro, не
произвольный CSS), `icon` (из фиксированного набора символов), `confirm` (опасное: выполняется вторым касанием), `action`.
Действие пока одно: `scene` — сменить сцену OBS (сцена должна быть в списке OBS).

```json
{"rev": 1, "groups": [
  {"id": "scenes", "name": "Scenes", "tiles": [
    {"id": "game", "x": 0, "y": 0, "w": 2, "h": 1, "label": "Game", "color": "blue", "action": {"type": "scene", "scene": "Game"}}
  ]}
]}
```

## API
| метод | путь | |
|---|---|---|
| GET | `/deck` | страница (SSR) |
| GET | `/api/deck/state` | `{rev, online, scene}` — опрос раз в 2 с (позже заменится WebSocket) |
| POST | `/api/deck/press` | `{tile, confirm}` — нажатие; нужен заголовок `X-Overlay-Composer: 1` |
| GET | `/api/deck/layout` | раскладка + сцены, `palette` (имя→цвет), `icons` (имя→символ), сетка (ряды, размеры плиток) для редактора |
| PUT | `/api/deck/layout` | сохранить; `rev` в теле должен совпасть с текущим, иначе 409 |
| DELETE | `/api/deck/layout` | вернуть раскладку по умолчанию |

## Безопасность
- Клиент присылает только `id` плитки. Действие берётся из сохранённой раскладки на сервере: устройство не может вызвать произвольный маршрут
  или сцену. Неизвестная плитка — 404; сцены, которой нет в OBS, — 404.
- Опасные плитки (`confirm`) сервер выполняет только с `confirm:true` (второе касание), иначе 409.
- Нажатия ограничены по частоте (всплеск 16, затем 8/с).
- Доступ с других устройств — по токену сопряжения (`authGuard`); `POST/PUT/DELETE` требуют заголовок приложения (защита от чужих страниц).
- Страница отдаётся с CSP: только свои inline-стили/скрипт и запросы на тот же адрес; метки и сцены экранирует `html/template`.

## Редактор

Кнопка **▦ Deck** в шапке редактора. Группы показаны полосой слева направо, как на планшете; плитки перетаскиваются мышью (в том числе
между группами), «+ Tile» добавляет плитку выбранного размера на первое свободное место (сцена — первая ещё не использованная).
Свойства выбранной плитки: подпись, сцена, цвет, значок, размер (только те, что помещаются), «confirm». Сохранение — кнопкой Save;
если раскладку тем временем изменили в другом месте (409), предлагается перечитать. При закрытии с несохранённым спрашивает.
Код: `web/client/editor/features/deck/` (`ops.ts` — чистые операции, `model.ts` — состояние и API, `view.ts` — DOM).
