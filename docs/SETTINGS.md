# Экспорт и импорт настроек

Настройки OC можно сохранить одним файлом `oc-settings.json` и перенести на другой компьютер (основа синхронизации с облаком, #98). Секреты в файл не попадают: токены Twitch,
пароли, ключи, устройства, токен магазина.

## Формат
```json
{ "format": 1, "app": "0.12.0", "createdAt": "2026-11-20T09:00:00Z",
  "sections": { "layouts": { … } }, "checksums": { "layouts": "<sha256 компактной записи секции>" } }
```
- Секции независимы: экспортировать и импортировать можно любую.
- Контрольные суммы ловят порчу и ручную правку (это не подпись); переформатирование файла им не мешает.
- Файл новее известного формата отклоняется с просьбой обновить OC; секция, которой эта версия не знает, пропускается (в плане она показана как неизвестная).
- Предел размера — 6 МБ.

## API (только с этого компьютера)
- `GET /api/settings/export?sections=a,b[&download=1]` — файл (пусто — все секции).
- `POST /api/settings/import/plan` (тело — файл) — проверка и план по секциям: у каждого элемента статус `new` / `replace` / `same` / `problem` (+ причина). Ничего не меняет.
- `POST /api/settings/import/apply` `{file, selection: {секция: {id: "replace" | "copy"}}}` — применяет выбранное. Выбрать можно только то, что есть в плане и не `problem`/`same`.

Перед первым изменением OC сохраняет текущие настройки в `<data>/backups/oc-settings-<время>.json` (последние 10); не удалось сохранить — ничего не меняется.
Секции применяются по порядку, зависимости раньше зависимых; ошибка одной секции не откатывает остальные и попадает в отчёт.

## Секции
Интерфейс секции — `internal/bundle.Section` (`Export`, `Plan`, `Apply`). Секции подключаются в `Server.settingsSections` по порядку применения.

### `sources` — источники
- Экспортируются все источники; **выданные права (`granted`) в файл не идут**.
- Импорт проверяет каждый источник теми же правилами, что создание через API (id, имя, тип, URL, прокси, роутер; настройки плагина — по его схеме). Негодное — `problem` с причиной.
- Плагина ещё нет (например, wasm-плагин из секции `plugins`, который будет установлен) — источник импортируется с предупреждением, а из настроек остаются только простые значения.
- Источник с тем же id заменяется; **локальные права остаются** (если плагин тот же; для другого плагина права сбрасываются). Режим «копия» для источников не поддерживается.

### `layouts` — layouts
- Экспортируются layouts (canvas, объекты, привязки к сценам) и id layout по умолчанию (для информации: локальный выбор по умолчанию не меняется). Локальный `rev` в файл не идёт.
- Статусы: `new`, `replace` (есть другой layout с тем же id — заменить или импортировать копией), `same`, `problem` (не проходит проверку).
- Привязка к сцене OBS, занятой другим layout, переходит к импортируемому — в плане об этом предупреждение.
- Копия получает свободный id (`id-2`…), имя «… (imported)», без привязок к сценам и без связей виджетов между layouts (`instanceId`).
- Объекты, чьих источников нет локально, пропускаются (в отчёте — заметка): импортируйте источники вместе с layouts.

### `deck` — панель Deck
- Один элемент `layout`: раскладка панели (группы, плитки, папки, плитки плагинов). Если своей раскладки нет (используется по умолчанию), секция в файле пустая.
- Раскладка читается теми же строгими правилами, что при сохранении из редактора панели (неизвестные поля, пересечения плиток, пределы); негодная — `problem` с причиной.
- Статусы: `new` (своей нет), `same`, `replace`. Предупреждения (не мешают импорту): сцены, которых нет в OBS (только если OBS подключён), и плагины, которых нет — плитки останутся, но не сработают, пока не появятся сцена или плагин.
- Применяется заменой; ревизия ставится выше текущей, поэтому подключённые устройства сразу перерисуются. Режим «копия» не поддерживается.

### `plugins` — автономные плагины
- В файле lock (`id, repo, tag, version, sha256, size`, см. «Lock-файл и восстановление» в `docs/WASM_PLUGINS.md`) и выданные права плагинов из lock.
- План берётся из `WasmLockPlan`: `ok` → `new`, `installed` → `same`, `differs` → `replace`; `deprecated` (с заменой), `removed`, `changed`, `no-source`, `unavailable`, `conflict`, `invalid` → `problem` с причиной.
- Импорт ставит ровно записанный релиз (тег и sha256 из lock). **Сохранённые права выдаются, только если sha256 загруженного плагина совпал с lock** и только те, что плагин запрашивает; остальные запрошенные права остаются невыданными — в отчёте о них заметка. Источник из lock сам не добавляется.

### `plugin-settings` — настройки плагинов (необязательная)
- Настройки (config) загруженных плагинов. Могут содержать токены и адреса, поэтому секция **не попадает в экспорт по умолчанию**: только если названа явно (`?sections=plugin-settings`). В локальный бэкап перед импортом попадает всегда (файл остаётся на этом компьютере).
- Плагин должен быть уже установлен: сначала импорт `plugins`, потом отдельный импорт настроек. Применение заменяет настройки и перезапускает плагин. Элементы в модалке по умолчанию не отмечены (`optional`).

### `store` — источники магазина
- Список репозиториев, добавленных в магазин. Токен GitHub не экспортируется.
- Добавить источник — значит довериться плагинам из этого репозитория, поэтому элементы **не отмечены по умолчанию** (`optional`) и сами не добавляются. Добавление проверяет репозиторий (скачивается, есть плагины); ошибка попадает в отчёт.
- Секция применяется раньше `plugins`: lock ссылается на источники (иначе запись получит `no-source`).

### `app` — подключение к OBS
- Единственный элемент `obs`: включено ли подключение и адрес (`ws://…`). Пароль OBS не экспортируется — после импорта его нужно ввести в настройках.
- Не отмечен по умолчанию: адрес OBS зависит от компьютера. Применение переподключает OBS сразу, как из окна настроек.
- Не переносятся: адрес и порт сервера, порт прокси, `noUpdateCheck`, `debugProxy`, секреты и ключи — они привязаны к компьютеру или секретны.

## В редакторе
Настройки → **Backup**:
- **Export:** галочки секций (по умолчанию все, кроме «Plugin settings» — там могут быть токены) и кнопка «Download settings file». Файл скачивается с сервера как есть.
- **Import:** выбор файла открывает переходную модалку. Ничего не меняется, пока не нажать «Import»: модалка показывает секции и элементы с отметками. Проблемные — красным с причиной (недоступны для выбора), с предупреждением — жёлтым, «already the same» — без выбора, необязательные (источники магазина, настройки плагинов, OBS) не отмечены. У layout со статусом «replaces yours» можно выбрать «Import as a copy». Секция, которой эта версия OC не знает, пропускается. После применения — отчёт по каждому элементу и обновление списков источников и layouts.
- Файл на клиенте не разбирается и не собирается заново (`RawJson`): контрольные суммы считаются по исходным байтам, повторная сборка JSON (порядок ключей, числа) их бы сломала.

## Облако (Settings → Backup → Cloud storage)

Файл настроек можно держать в облаке; ничего не загружается и не применяется само — только кнопки Upload / Import… / Replace / Delete. Скачанный из облака файл идёт в тот же импорт с выбором элементов.

- **Папка** — любой каталог, который синхронизирует Dropbox, OneDrive, Google Drive для компьютера, Syncthing и т.п. (`internal/cloud/folder.go`).
- **Google Drive** — скрытая папка приложения (`appDataFolder`), scope `drive.appdata`: файлы не видны в интерфейсе Drive и доступны только этому OAuth-клиенту. Авторизация OAuth с PKCE, возврат на `http://127.0.0.1:<порт>/auth/google/callback`; refresh-токен хранится в БД зашифрованным (`cloud_google_refresh`). OAuth-клиент (тип Desktop) встроен в сборку: `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` передаются в `go run ./cmd/build` (в CI — секреты репозитория с теми же именами). Для локальной сборки (`make windows`) положите их в файл `.env` в корне репозитория (строки `GOOGLE_CLIENT_ID=...` и `GOOGLE_CLIENT_SECRET=...`; файл в git не попадает); переменные окружения важнее файла; из `.env` читаются только эти два ключа, в окружение процесса они не попадают, а в логе сборки заменяются на `***`. Без ключей сборка работает, но подключение Google Drive недоступно.
- Замена существующего файла возможна только с отпечатком (sha256) известной версии; иначе 409 и ничего не меняется.

API (только с этого компьютера): `GET|PUT|DELETE /api/cloud`, `POST /api/cloud/google/start`, `GET /api/cloud/files`, `POST /api/cloud/upload {name?, sections?, expect?}`, `GET|DELETE /api/cloud/files/:id` (скачивание отдаёт `{id, text}` — исходный текст файла).
