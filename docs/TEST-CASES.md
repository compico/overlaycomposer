# Тест-кейсы: сквозная проверка Overlay Composer

Чек-лист для ручной проверки «от начала до конца» на настоящей машине (OBS, Twitch, tosu, второе устройство).
Автотесты и подставное окружение уже проходят — здесь только то, что они **не** покрывают.

**Как читать.** В каждом разделе сначала идут **sad path** кейсы (ошибки, отказы, граничные случаи), потом happy path.
Кейс — это `[ ]` + id + название; «Ожидаем» — что должно произойти. **★** — минимальный прогон (если мало времени, пройдите только ★ — это 76 кейсов, ~2,5–3 часа; все 173 — полдня).
Нашли расхождение — пишите id кейса, что увидели, что ждали, фрагмент лога (`⚙ Settings → Open log folder`).

## 0. Подготовка

| Что | Зачем |
|---|---|
| Сборка из `main`: `go build ./... && go test -race ./...` затем `make dev` или `make windows`/`make linux` | первый раз `internal/server`, `cmd`, SQL-слой собираются вне среды разработки — **любая ошибка сборки/тестов уже находка** |
| Чистая папка данных: `overlay-composer --home /путь/test-home` | портативный режим, не трогает рабочие данные; для «первого запуска» удалите папку |
| OBS 28+ (встроенный obs-websocket 5), 3 сцены: `Game`, `Chat`, `Empty` | привязки сцен, переключение |
| Приложение Twitch (dev.twitch.tv/console, **Confidential**), два аккаунта: Streamer и Bot, чат канала открыт в браузере | аккаунты, чат-API |
| tosu + osu!, любая карта с сайта и одна локальная (не загруженная) | `osu-np` |
| Второе устройство в той же сети (телефон/планшет), IP компьютера | внешний доступ |
| `curl`, Chrome DevTools | проверки безопасности |
| Публичный GitHub-репозиторий-пустышка без плагинов (создайте любой), плюс `compico/oc-plugins` | магазин |
| Windows-машина (для раздела 13) | трей, автозапуск, exe |

Для раздела 14 дополнительно понадобятся: приватный репозиторий GitHub и fine-grained токен, `sqlite3`, предыдущая версия приложения (для миграции).

Договорённости: адрес редактора `http://127.0.0.1:8000/editor`, оверлей `http://127.0.0.1:8000/overlay`, в OBS — один Browser Source 1920×1080 с оверлеем во всех сценах.

## 1. Запуск и приложение

**Sad path**
- [ ] **1.1★ Порт занят.** Займите порт 8000 (`python3 -m http.server 8000`) и запустите приложение. Ожидаем: окно/сообщение об ошибке с понятным текстом (порт, куда смотреть конфиг), процесс завершается, второй экземпляр не создаётся.
- [ ] **1.2 Битый `config.json`.** Испортите JSON в конфиге, запустите. Ожидаем: понятная ошибка (или запуск с умолчаниями, но без потери файла молча), без паники.
- [ ] **1.3★ Битый `market.json`.** Испортите `data/market.json`, запустите. Ожидаем: окно ошибки «Не удалось прочитать список магазина плагинов…», выход с ненулевым кодом; после удаления файла приложение стартует.
- [ ] **1.4 Нет прав на запись в папку данных** (read-only каталог для `--home`). Ожидаем: понятная ошибка, а не молчаливый вылет.
- [ ] **1.5 Второй запуск.** Запустите приложение дважды. Ожидаем: второй экземпляр не поднимает сервер, а открывает редактор в браузере и выходит.
- [ ] **1.6 `--no-open`, `--no-tray`, `--autostart`.** Ожидаем: браузер не открывается / нет значка в трее (работает до Ctrl+C) / при `--autostart` браузер не открывается.
- [ ] **1.7 Остановка во время работы OBS.** «Quit Overlay Composer» (диалог подтверждения) при открытом оверлее в OBS. Ожидаем: сервер остановлен, виджеты в OBS остаются как были, после повторного запуска страница сама переподключается (без ручной перезагрузки источника).

**Happy path**
- [ ] **1.8★ Первый запуск.** Пустая папка данных. Ожидаем: открывается редактор, есть один пустой layout «Default», в `data/` создана база, в `plugins/` пусто, в `data/market.json` — источник `compico/oc-plugins`.
- [ ] **1.9 Перезапуск сохраняет всё** (layout, источники, привязки, настройки OBS/Twitch, список устройств, данные плагинов, список магазина).
- [ ] **1.10 Settings → Open data folder / Open log folder / Open plugins folder** открывают правильные папки.
- [ ] **1.11 `--version`** печатает версию.

## 2. Редактор: layout и слои

**Sad path**
- [ ] **2.1★ Несохранённые изменения.** Подвигайте слой, переключите layout в выпадающем списке. Ожидаем: «Discard unsaved changes?»; Cancel — остаёмся, список возвращается на текущий layout; OK — правки отброшены.
- [ ] **2.2 Закрытие вкладки с несохранённым** — разумное поведение (хотя бы бейдж «unsaved»); после повторного открытия состояние = последнее сохранённое.
- [ ] **2.3★ Удаление layout с привязками.** Привяжите layout к сцене, удалите. Ожидаем: подтверждение; сцена теперь показывает default; в OBS overlay переключился.
- [ ] **2.4 Удаление источника, который стоит в нескольких layout.** Ожидаем: `Delete source "…" from ALL layouts?`; после OK слои исчезли из всех layout, без ошибок в консоли.
- [ ] **2.5 Некорректные значения.** В полях X/Y/ширина/высота/опасность: пусто, `0`, отрицательные, очень большие, текст. Ожидаем: значение не ломает слой (зажимается/игнорируется), нет `NaN` на холсте.
- [ ] **2.6 Слой за пределами холста / очень маленький** (ширина 1 px). Ожидаем: можно выбрать через список слоёв и вернуть.
- [ ] **2.7 Два слоя друг на друге.** Alt+клик перебирает слои по кругу; выбор нижнего из списка слоёв работает.
- [ ] **2.8 Две вкладки редактора.** Сохраните layout в одной, измените в другой и сохраните. Ожидаем: последнее сохранение побеждает, без падения (известное ограничение: нет защиты `rev`, см. TODO).
- [ ] **2.9 Add Source: пустое имя/URL.** Ожидаем: тост «Name and URL are required»; невалидный URL (`foo`, `javascript:alert(1)`) — отказ или безопасный пустой виджет, но не выполнение скрипта.

**Happy path**
- [ ] **2.10★ Add Source → URL** (например, любой алерт-виджет или `https://example.com`), поставить на layout, двигать/растягивать/поворачивать, прозрачность. Save (Ctrl+S) → в оверлее то же.
- [ ] **2.11 New / Duplicate / Delete layout, переименование слоя двойным кликом, порядок слоёв (z), lock/visible.**
- [ ] **2.12 Отмена изменений и перезагрузка страницы редактора** — всё как после последнего Save.

- [ ] **3.6 Crop + поворот + масштаб одновременно**: содержимое остаётся на месте при обрезке, вращение вокруг центра видимой части.
- [ ] **3.7 Layout с другим размером холста** (если есть): позиция переносится как есть без масштабирования (известное ограничение).

- [ ] **3.8★ Linked-копия:** слой с «живым» состоянием (чат/таймер/алерт) → Copy to layout (Keep linked), переключите сцену в OBS туда-обратно. Ожидаем: виджет **не перезагружается** (состояние сохранилось). Независимая копия (без галочки) — перезагружается.
- [ ] **3.9★ Crop мышью:** Alt+тяга боковой ручки и угловой; поля *Crop (px)*; *Reset crop*; в OBS то же, что в редакторе.

## 4. OBS: сцены, привязки, импорт

**Sad path**
- [ ] **4.1★ OBS не запущен.** Бейдж «OBS: …» показывает отсутствие связи; редактор работает; после запуска OBS подключение появляется само (≤ нескольких секунд) без перезапуска.
- [ ] **4.2★ Неверный пароль obs-websocket.** Ожидаем: понятный статус ошибки в Settings, без бесконечного спама в логе, после исправления пароля + «Reconnect now» — подключение.
- [ ] **4.3 Неверный URL** (`ws://127.0.0.1:1`). Ожидаем: статус «не удаётся подключиться», приложение живо.
- [ ] **4.4 Сцена привязана к двум layout.** Привяжите одну сцену к другому layout и сохраните. Ожидаем: сцена принадлежит только одному layout (у первого пропала).
- [ ] **4.5★ Сцена без layout.** Переключитесь на сцену без привязки. Ожидаем: показывается layout «по умолчанию»; если default не задан — пусто, без ошибок.
- [ ] **4.6 Ручной выбор layout (▶) и смена сцены:** ручной выбор не сбрасывается, пока сцена не «положит» другой layout.
- [ ] **4.7 Быстрое переключение сцен** 10 раз подряд. Ожидаем: оверлей приходит в финальное состояние, нет залипаний, сайт виджета не отвечает `Too Many Requests` (если отвечает — это известный пункт TODO, запишите).
- [ ] **4.8★ Импорт сцены с группами/вложенными сценами, поворотом, скрытыми и не-браузерными источниками.** Ожидаем: отчёт перечисляет не перенесённое (crop, отражение, фильтры, локальные файлы, не-браузерные); внешние сайты получают proxy, `localhost` — напрямую; положение/размер/поворот/порядок/видимость совпадают.
- [ ] **4.9 Импорт повторно / без obs-websocket.** Ожидаем: список сцен пуст или понятная подсказка, второй импорт не затирает существующий layout (создаётся новый).
- [ ] **4.10 Overlay-страница не в OBS** (обычный Chrome): список сцен идёт из obs-websocket; без него — пусто, без ошибок.

**Happy path**
- [ ] **4.11★ Три сцены, три layout, один default.** Переключение сцен в OBS меняет layout за ≈ 1 с; бейджи в редакторе показывают текущую сцену.
- [ ] **4.12 Имя сцены вручную («Add scene by name…»)** для сцены, которой ещё нет в OBS; после создания в OBS привязка работает.
- [ ] **4.13 Переименование сцены в OBS** — как обрабатывается привязка (запишите наблюдаемое поведение).

## 5. Виджеты по URL и proxy

**Sad path**
- [ ] **5.1★ Сайт запрещает встраивание** (DonationAlerts/любой с `X-Frame-Options`). Без proxy — пусто; включите **proxy** — виджет работает, WebSocket живёт.
- [ ] **5.2 Недоступный/медленный сайт** через proxy: ошибка в логе (`proxy: ответ с ошибкой`), оверлей и остальные виджеты не зависают.
- [ ] **5.3 Блокируемые трекеры** (`proxy.BlockedHosts`) — страница виджета не рвётся.
- [ ] **5.4 Два proxy-виджета с одинаковым путём** (`/assets/index.js`) — известное ограничение; зафиксируйте, ломается ли один из них.
- [ ] **5.5 Proxy WS с Cookie/Authorization** (известное ограничение): запишите, если виджет отвечает 401.
- [ ] **5.6 Open redirect/SSRF-проверка:** через proxy запросите `http://127.0.0.1:8000/api/config` в качестве источника. Ожидаем: поведение понятное и безопасное (запрос к самому OC не должен отдавать данные не-локальному клиенту; запишите результат).

**Happy path**
- [ ] **5.7★ Виджет с `localhost` URL** (например, tosu overlay) — напрямую, без proxy.
- [ ] **5.8 Виджет через proxy в OBS (CEF)** ведёт себя так же, как в Chrome.

## 6. Доступ с других устройств

**Sad path**
- [ ] **6.1★ По умолчанию (Listen on = 127.0.0.1).** С другого устройства открыть `http://<IP>:8000/` — недоступно; блок «Remote devices» в настройках скрыт или поясняет, что включить.
- [ ] **6.2★ Неверный код** на `/pair` (5 раз подряд). Ожидаем: 403 «bad code», затем 429 «too many attempts» и блокировка адреса на 5 минут; верный код в этот период тоже отклоняется; через 5 минут — работает.
- [ ] **6.3★ Код одноразовый и устаревает.** Введите код дважды (второй раз тем же), введите код старше минуты. Ожидаем: отказ.
- [ ] **6.4★ Доступ без токена:** со второго устройства `http://<IP>:8000/editor` → редирект на `/pair`; `curl http://<IP>:8000/api/layouts` → 401 `unauthorized`.
- [ ] **6.5★ Управление только с компьютера.** Сопряжённое устройство: `GET /api/devices`, `/api/twitch`, `/api/market` → 403 «available only from this computer»; в редакторе блоки «Remote devices»/«Twitch accounts» не показаны.
- [ ] **6.6★ Отзыв устройства (Revoke).** Устройство получает 401 при следующем запросе; уже открытая страница после переподключения WS — на `/pair` (известное: открытое соединение живёт до переподключения — запишите, сколько).
- [ ] **6.7 Прокси/туннель:** запрос с `X-Forwarded-For` к `127.0.0.1` считается внешним и требует токен (`curl -H 'X-Forwarded-For: 1.2.3.4' http://127.0.0.1:8000/api/layouts` → 401).
- [ ] **6.8 Кража cookie:** токен из cookie другого устройства работает с другого IP (бессрочный токен) — запишите наблюдаемое.

**Happy path**
- [ ] **6.9★ Сопряжение:** Listen on = All network interfaces → Save → перезапуск; на телефоне `/pair`, ввод кода → попадаете в редактор; в Settings → Remote devices устройство в списке с понятным именем.
- [ ] **6.10 Оверлей на втором устройстве** (`/overlay`) показывает layout; обновляется при смене сцены.
- [ ] **6.11 Перезапуск приложения:** устройство остаётся сопряжённым (токен переживает перезапуск).

- [ ] **7.4 Отмена на странице Twitch (Deny).** Ожидаем: страница-результат «не подключено», роль не меняется.
- [ ] **7.5 Подключить один и тот же аккаунт как Streamer и как Bot.** Ожидаем: понятное поведение (разрешено или явный отказ) без дубляжа сообщений в чате.
- [ ] **7.6★ Отзыв доступа на twitch.tv/settings/connections.** Ожидаем: при следующем обновлении токена/отправке аккаунт помечается как требующий переподключения, без цикла ошибок в логе.
- [ ] **7.7 Смена Client ID** при подключённых аккаунтах: предупреждение; аккаунты отключаются (их токены принадлежат старому приложению).

- [ ] **7.9 Callback с чужой страницы/устройства:** `/auth/twitch/callback?code=x&state=y` с другого устройства → 403; с неверным `state` → отказ.
- [ ] **7.10 Disconnect** → токен отозван на Twitch (аккаунт пропал из списка), повторное подключение работает.

**Happy path**
- [ ] **7.11★ Подключить Streamer и Bot** (разные аккаунты): в списке видны логины; после перезапуска OC остаются подключёнными; токены **не** видны в `GET /api/twitch` и в сетевых вкладках редактора.
- [ ] **7.12 Автообновление токена:** оставьте на 4+ часа (или сократите время вручную) — аккаунт остаётся подключённым.

## 8. API плагинов: чат и разрешения

**Sad path**
- [ ] **8.1★ Нет разрешений.** Добавьте плагин с `chat.read`/`chat.send`, на вопрос о разрешениях ответьте **Cancel**. Ожидаем: виджет показывает «Missing permissions» (для `osu-np`), в логе нет попыток подписки; чат не читается.
- [ ] **8.2★ Отзыв разрешения «на лету».** В свойствах слоя снимите `chat.send`, перезагрузите оверлей. Ожидаем: `say` отклоняется «permission denied: chat.send», `chat.read` продолжает работать.
- [ ] **8.3★ Нет подключённого аккаунта.** Отключите Bot и Streamer, плагин пытается `say`. Ожидаем: понятная ошибка, а не молчание/падение; чтение (анонимное) работает.
- [ ] **8.4 Нет интернета/Twitch недоступен.** Ожидаем: статус чата «reconnecting», автоматическое переподключение, плагин не падает; после восстановления подписка возобновляется.
- [ ] **8.5 Спам:** отправьте из плагина >18 сообщений за 30 с. Ожидаем: часть отклонена лимитом, без бана аккаунта.
- [ ] **8.6★ Дубль оверлея.** Откройте оверлей в двух местах (OBS + Chrome) и отправьте команду. Ожидаем: ответ в чате **один** раз.
- [ ] **8.7 Предпросмотр редактора:** чат читается, `say` отключён (ответов от редактора нет).
- [ ] **8.8★ Плагин из sandbox не ходит в API напрямую:** в DevTools iframe плагина `fetch("/api/config")` и `new WebSocket("ws://127.0.0.1:8000/ws")` → отклонены (CORS/Origin 403); `curl -X POST http://127.0.0.1:8000/api/layouts -H 'Origin: http://evil.example' -H 'content-type: application/json' -d '{"name":"x"}'` → 403 `cross-origin request`.
- [ ] **8.9 Сообщения с эмодзи, длинные, на других языках, удаление (`/delete`), `/clear`:** события `delete`/`clear` приходят, плагин (Twitch Chat) их показывает.
- [ ] **8.10 Токены не утекают:** в Network/WS-фреймах редактора и оверлея нет строк `oauth:`/access-токенов.

**Happy path**
- [ ] **8.11★ Встроенный Twitch Chat** (Add Source → Twitch Chat, ваш канал): сообщения появляются в оверлее и в предпросмотре; настройки (шрифт, цвета, фон) применяются; в OBS (CEF) шрифты/цвета/эмодзи корректны; реконнект после обрыва сети.
- [ ] **8.12★ Один чат-коннект на несколько виджетов:** два плагина слушают один канал; в логе одно соединение с IRC на канал (не по соединению на плагин).
- [ ] **8.13 Бот пишет от своего имени**, Streamer — от своего (`as: "bot" | "streamer"`).

## 9. Хранилище плагинов

- [ ] **15.10★ Все пути выхода.** Повторите 15.9 для Quit из ⚙ Settings, из трея и по Ctrl+C (запуск из консоли, `--no-tray`). Ожидаем: во всех случаях `stopped` записывается.
- [ ] **15.11 Две копии плагина.** Оверлей в OBS и предпросмотр в редакторе одновременно. Ожидаем: `count` вырос на 2 (обе копии вызваны), значения не потеряны.
- [ ] **15.12 `chat.say` при остановке.** Включите настройку «Say on stop», аккаунты Twitch подключены. Quit. Ожидаем: в чате появляется «stoptest: goodbye» (из оверлея; предпросмотр редактора не пишет в чат).
- [ ] **15.13 Установка/удаление в магазине после остановки не ломаются:** после 15.9 обновите/удалите плагин из магазина — данные `stopped`/`count` на месте (удаление плагина не стирает данные).

### Известные ограничения (не считать ошибкой, но запишите наблюдаемое)
Нет защиты `rev` при сохранении из двух вкладок · позиция при копировании между layout с разным размером холста не масштабируется · открытое WS-соединение отозванного устройства живёт до переподключения · пароль obs-websocket хранится в `config.json` открытым текстом (токены Twitch и секреты зашифрованы — раздел 14) · один и тот же путь у двух proxy-виджетов · WS-прокси не передаёт Cookie/Authorization · обработчики магазина/сервера ранее не собирались вне среды разработки.
