# Редактор: структура клиента

Цель — чтобы редактор можно было постепенно перевести на фреймворк (React/Svelte/Vue), не переписывая логику.
Поэтому код делится на слои, и **логика не знает про DOM**.

```
web/shared/            чистая логика без DOM и сети (types, geometry, history, snap) — тесты node:test
editor/lib/store.ts    реактивное хранилище: get / set / update / subscribe (контракт совпадает со Svelte store,
                       годится для React useSyncExternalStore и Vue shallowRef)
editor/lib/api.ts      тип `Api` (функция-запрос) и реальный `httpApi`; в тестах подставляется фейк
editor/lib/ui.ts       тип `Ui` {toast, fail} — что представлению нужно от окружения
editor/lib/dom.ts      $ и el — помощники ванильных представлений
editor/features/<имя>/
    model.ts           состояние в Store + действия; зависит только от `Api`; интерфейс — `XModel`
    view.ts            ванильный DOM: mountX(refs, model, ports); refs — элементы, ports — всё остальное снаружи
    model.test.ts      тесты модели с фейковым `Api`
editor/main.ts         «склейка»: общее состояние layout, канвас, панели, которые ещё не вынесены
```

## Правила

1. **Модель** (`model.ts`) не импортирует DOM, `fetch`, `window`. Всё внешнее приходит параметрами (`Api`, другие модели).
2. **Представление** получает модель и *утиные* «порты» (маленькие интерфейсы: `Ui`, `openStore()` …), а не обращается к глобальным функциям `main.ts`. Так его можно заменить компонентом, не трогая модель.
3. Зависимости между фичами — через интерфейсы моделей/портов, не через общие переменные модуля.
4. Новая фича — сразу в `features/<имя>/` по этой схеме; при правке старого кода из `main.ts` стоит выносить его туда же.

## Переход на фреймворк (как это выглядит)

Для каждой фичи пишется компонент, который читает `model` (`useSyncExternalStore(model.subscribe, model.get)` в React,
`$model` в Svelte) и вызывает его действия; `model.ts` остаётся без изменений вместе с тестами. Старое `view.ts` удаляется.
Переносить можно по одной фиче: ванильные и фреймворк-представления спокойно живут вместе.

## Что уже вынесено

- `editor` — центральная модель: layouts/sources/plugins, рабочая копия layout, выбор, «несохранённое», история (undo/redo), загрузка, сохранение, слои (добавить/удалить/порядок/видимость/блокировка/имя), операции над layout (создать/дублировать/удалить/активный). Каждое изменение приходит с `change: ChangeKind`, по нему `main.ts` решает, что перерисовать. Рабочая копия правится на месте (жесты на канвасе меняют transform каждый кадр); `main.ts` держит только читаемое «зеркало» состояния.
- `store` — каталог плагинов, источники, токен GitHub, установка/удаление.
- `app`, `config`, `twitch`, `devices` — части окна настроек.
- `obs-import`, `scene-binding` — импорт сцены из OBS и привязка layout к сценам.
- `notifications` — центр уведомлений.
- Инфраструктура `lib/` (store, api, ui, dom) и чистая логика в `web/shared/` (history, snap, geometry).

## Что НЕ перенесено (всё ещё в `main.ts`, ~1350 строк)

Из `main.ts` ушли state, loading, history, save, selection и действия над слоями/layout; остался DOM и жесты.

| Раздел | Что внутри | Что мешает вынести | Сложность |
|---|---|---|---|
| rendering (канвас) | рамки, ручки, перетаскивание, ресайз, обрезка, поворот, hit-test, направляющие | самый плотный DOM+события; разумно оставить императивным и в фреймворке | высокая |
| layouts panel (view) | рендер списка layout и кнопок | только DOM; логика уже в `editor` | низкая |
| layers panel (view) | рендер слоёв, drag-порядок | только DOM; логика уже в `editor` | низкая |
| properties panel | панель свойств слоя/layout, форма настроек плагина | много DOM; значения пишутся в рабочую копию напрямую и вызывают `editor.touch()` | средняя |
| copy between layouts | Ctrl+C/V между layout, диалог | использует `editor.insertObject`, но диалог и буфер остаются в `main.ts` | средняя |
| add source | диалог «Add Source» (вкладки, Twitch-ссылки) | много DOM | средняя |
| layout mode and snapping | настройки (localStorage), цели прилипания, направляющие | настройки — маленькая модель; рисование — часть канваса | низкая |
| keyboard | горячие клавиши | диспетчер, который знает все действия; станет «командами» | средняя |
| websocket | `/ws`: сцена, OBS-статус, обновления | вызывает `editor.*` и рендер; станет источником событий | средняя |

Следующие шаги: view панелей Layouts/Layers/Properties как отдельные `view.ts` над `editor` → keyboard/websocket как команды и события → канвас последним.
